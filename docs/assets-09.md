# Afterlight 0.9: environments, asset jobs and light tools

All engine, editor and gameplay code remains C17. This milestone completes the
six follow-ups to 0.8. Start the updated Lighting Lab with:

```sh
cmake --preset debug
cmake --build --preset debug --target run_lighting_editor
```

## GitHub build check and Linux CI

The first pushed 0.8 build passed all three [macOS build configurations](https://github.com/TurboRigby/Afterlight/actions/runs/42133358049),
and [C/Python CodeQL](https://github.com/TurboRigby/Afterlight/actions/runs/42133355492)
also passed. No repair to that remote build was needed.

The workflow now additionally builds Debug, Release and ASan/UBSan configurations
on Ubuntu 24.04. The same `.github/scripts/linux-build.sh` runs locally on Linux.
Ubuntu 24.04's SDL2 package is insufficient: the script builds SDL3 3.4.16 from
an explicit upstream commit and installs it in the ignored build directory.
It never downloads dependencies implicitly during the engine's CMake configure.
CI permissions remain read-only; nothing publishes or pushes automatically.
Sanitizer Linux builds use Clang and `-O1`; ordinary Linux builds use GCC. This
avoids pathological GCC/ARM64 fake-stack allocation overhead observed in the
instrumented convolution tests while preserving AddressSanitizer/UBSan checks.
The optimization also helps to keep instrumented CPU convolution practical.
Hosted jobs run the CPU/source-distribution tests; interactive graphics tests
remain local GPU checks. A GitHub-hosted run of the added jobs requires pushing
the workflow. See [verification](testing.md).

## HDR environment assets

In the Inspector, scroll to **Environment lighting** and use **Import HDR
environment**. The Assets panel also has **Import HDR panorama** and an HDR
filter. Import creates an `environment` asset, selects it for lighting and enables
its skybox. **Environment source** switches between imported assets and the
original procedural profiles. Environment intensity affects lighting; rotation
affects lighting and background together. Enable tone mapping for HDR highlights.

The loader accepts Radiance RGBE `.hdr` equirectangular panoramas up to 4096x2048,
64 MiB encoded / 128 MiB decoded. It verifies complete scanlines before decoding
and rejects nonfinite, negative or above-65504 radiance. LDR textures still use
the separate PNG/JPEG/BMP/TGA path. OpenEXR, cubemap imports and color management
metadata are not implemented. The source must already be in linear RGB.

Imported floating-point radiance supplies diffuse convolution, GGX prefiltered
specular levels and the split-sum BRDF. Bilinear CPU sampling wraps longitude and
clamps latitude. The full-resolution source supplies the skybox; the existing
128x64 specular and 32x16 diffuse baking resolutions remain bounded. HDR loading,
convolution and initial environment upload currently run synchronously. Up to
16 environment resource sets can be resident; staged reloads use the same budget.

Save/load, undo/redo, cloning, watched/manual reload and export preserve the
named environment asset. A failed decode or staged rebuild retains the previous
GPU data. A missing selected resource falls back to the procedural environment
and is counted in missing-texture diagnostics. The original `studio.hdr` and
matching test panorama are regenerated by
`python3 scripts/generate_environment_assets.py`; no external art is bundled.

## Skyboxes

**Show environment skybox** and **Background brightness** are independent of
the IBL switch/intensity. The background rotates with the environment and follows
camera direction while ignoring camera translation. It renders inside the scene
viewport before opaque geometry, without writing depth. It is part of the HDR
scene and therefore receives exposure/tone mapping and can contribute to bloom.
Editor panels/text remain in display space afterwards. Disabling the skybox
restores the regular clear color. Visible skies work with empty scenes as well.

## Asynchronous thumbnails

Visible asset/material previews enqueue immutable snapshots into a bounded
eight-job queue. A dedicated SDL worker performs file decoding and CPU preview
rasterization; it never reads the live document or calls Vulkan/Nuklear. The
main thread polls completed results, discards stale generations, and queues at
most one GPU upload per frame. The existing 64-entry cache retains last-good
previews on failed replacement and reacts to file signatures, dependency reloads
and material edits. HDR panoramas receive tone-mapped previews.

Overlay image uploads now record staging copies/barriers in normal frame
commands. Replaced/removed images retire only after the owning frame fence,
keeping in-flight descriptors valid. This path uses neither a device-idle nor
queue-idle wait. It limits queued CPU pixels to 64 MiB and resident IDs to 128;
pending updates to one ID coalesce. The UI atlas and scene asset imports retain
their separate synchronous upload paths. Small GPU resource allocations and
file stat checks still occur on the main thread. On shutdown the worker is
stopped/joined and all jobs/snapshots/results are freed.

## Light gizmos

Point/spot light markers appear in the viewport while editing. Click a marker
to select its light and show its controls in the Inspector. The selected light
shows three range circles for a point light or inner/outer cone wires for a spot.
Markers are editor overlays and can be selected through geometry.

- **W / Move**: drag an axis to translate the light.
- **E / Rotate**: rotate the spot direction with the rotation rings.
- **R / Scale**: drag an axis to change the light range.
- **Snap** uses the existing gizmo snapping behavior.
- **F** focuses the camera on the selected light.
- **Delete** removes the selected light.
- Release ends a grouped edit; **Escape** cancels an active light drag.

The light dropdown and **Select light in viewport** also select lights. Object
selection restores object tools. Light changes use the normal scene history;
undo/redo and Play isolation apply. Lights remain a separate scene array, so
structural deletion can change indices and clear a now-invalid selection.
Cone/range wireframes are clipped editor guides, not physical light volumes.

## Persistence and regression checks

Scene format **9** adds `render.environment_asset` (name or empty string),
`render.skybox` and `render.skybox_intensity` [0,100], plus the `environment` asset
kind. Versions 1–8 remain readable; older scenes default to a hidden skybox and
procedural sources. Save writes v9. Game ABI is **8**: rebuild C game modules and
refresh copied headers in existing generated projects before loading them.

The milestone also fixes the editor's render-setting equality check so edits to
environment/bloom fields are no longer ignored when exposure remains unchanged.

Tests cover RGBE limits/truncation, seam sampling, real sky/IBL pixels, independent
background intensity, rotation/translation, viewport clipping, resize and reload
failure/recovery. CPU geometry checks cover point circles and spot cones; the
editor injects mouse events for light picking, drag, grouped undo/redo and Escape.
Thumbnail checks exercise asynchronous completion/invalidation and shutdown with
a queued job. Export tests include an HDR asset, delete the source project, move
the package and run the player with bundled resources.

Implementation references: [SDL worker threads](https://wiki.libsdl.org/SDL3/SDL_CreateThread),
[Vulkan synchronization](https://docs.vulkan.org/spec/latest/chapters/synchronization.html),
and the vendored stb_image RGBE decoder (original notices retained).
